# Evidence — 프론트엔드 시각 QA (2026-09-03)

## 방법

SwiftUI는 Windows에서 렌더링 불가 → 재구현 코드의 DesignTokens(실색상)·레이아웃·문구를
그대로 반영한 프리뷰(`preview/index.html`)를 제작, 로컬 HTTP(127.0.0.1:8137)로 브라우저
렌더링 후 **7개 화면 전부 스크린샷 촬영 → 원격 비전 모델(analyze_image)로 UI/UX 리뷰**.
스크린샷 원본: `preview/shots/*.png`

## 검증한 화면 (7/7)

intro(온보딩 환영) / rangetest(음역대 실측) / routine(일일 루틴) / tracker(피치 트래커) /
lab(발성 연구소) / tipdetail(팁 상세 시트) / progress(성장 기록)

## 종합 판정

- 구성·시각 위계·간격·테마 일관성: 7개 화면 모두 "깔끔/일관" 평가.
- 히트맵 7열 = 월화수목금토일 헤더 정렬 확인(progress 리뷰).
- 피치 트래커 캔버스/피아노 스트립/노트 디스플레이 일관성 확인(tracker 리뷰).
- 치명적 시각 결함(겹침/오버플로/깨진 레이아웃): **0건**.

## 비전 리뷰 지적 중 오판/아티팩트 판정 (사실확인 완료)

1. "한글 깨짐" 지적(다수 화면) → **저해상도 OCR 오판**. DOM `innerText`로 렌더된 실제
   텍스트를 추출해 정상 한국어임을 확인 (예: "삑사리", "파사지오(2옥 솔/라) 돌파",
   "오보컬 48개 쇼츠 비법" 전부 정상). 스크린샷 축소로 인한 글자 오식이었음.
2. "링 위 STEP 라벨 만곡/타이머 텍스트 만곡" → 원본에 만곡 요소 없음(정적 중앙 배치). 오판.
3. rangetest "일시정지(빨강)+측정완료(초록) 동시 표시 모순" → **프리뷰 목업이 불가능 상태를
   함께 그린 것**. 실제 앱 로직은 start() 시 hasResult 리셋되어 상태 충돌 불가(코드 확인).
4. 하단 잘림(tipdetail YouTube 행 등) → 실앱은 ScrollView라 스크롤됨. 프리뷰 프레임 아티팩트.
5. 대비 우려(textSecondary) → #94A3B8 vs #0A0E27 대비 약 7.6:1(WCAG AA 통과).

## 반영한 실제 개선 (앱 코드)

1. **가이드 키(남성/여성) 전환 UI 부재** — 온보딩은 "루틴 화면에서 변경 가능"이라 안내했으나
   루틴 설정 카드에 선택 UI가 없었음(재구현 코드의 실결함, 감사 중 발견).
   → DailyRoutineView에 세그먼트 픽커 추가(AppStorage 연동), DailyRoutineViewModel이
   UserDefaults를 직접 읖도록 수정. 2026-09-03 완료.
2. 온보딩 개인정보 캡션 `.opacity(0.8)` 제거(대비 개선).
3. 프리뷰 샘플 데이터 오류 수정: +12¢일 때 표시 주파수 337.4→331.9 Hz(정합).
