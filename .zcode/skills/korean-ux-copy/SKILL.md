# Korean UX Copy — AI티 제거

원칙: 카피는 이해를 돕는 재료이지 장식이 아니다. 문장 하나를 고치기 전에
"이 화면에서 사용자가 결정해야 할 것은 무엇인가"를 먼저 답한다.

## AI티 진단 체크리스트 (하나라도 걸리면 고친다)

1. **이모지가 문장 구실을 하는가** — 제목·완료 알림마다 🎉✨🚀가 붙으면 제거.
   이모지는 기능 구분자(카테고리 표시 등)로만 남긴다. 한 화면 1~2개 상한.
2. **광고 과장어** — "완벽한", "놀라운", "꿀팁", "핵심", "최고의", "혁신적인".
   구체적 수치·사실로 치환: "완벽한 음정" → "±12센트 이내".
3. **균등 리듬** — 모든 문장이 같은 길이·같은 어미("~합니다. ~합니다. ~합니다").
   길고 짧은 문장을 섞고, 명사형 종결로 마무리하는 문장도 하나쯤 둔다.
4. **빈 수식어** — "쉽고 재미있는", "더 나은", "간편한". 무엇이 쉬운지 말이
   없으면 삭제. 수식어를 지웠을 때 정보가 안 줄면 원래도 없던 것이다.
5. **번역투 소유격** — "당신의 목소리", "나만의 여정". 한국어 UI에서 '당신의'는
   거의 항상 생략 가능하다. "여정(journey)·시작해보세요·발전시키세요" 류도 같은 부류.
6. **감정 대신 지시** — 에러/빈 화면에서 사과·감탄 대신 원인과 다음 행동.
   "앗, 문제가 발생했어요!" → "마이크 권한이 꺼져 있어요. 설정에서 켜주세요."
7. **시스템 관점 명명** — 사용자가 모르는 내부 용어(webhook, 인스턴스) 노출.
   사용자가 조작하는 대상 이름으로 바꾼다.
8. **의미 없는 이중 감탄** — "!!", "!?", "ㅠㅠ" 등. 알림 제목에는 느낌표 0~1개.
9. **AI 문장 부호 습관** — em-dash(—) 과다, ":" 뒤 설명 나열 강박,
   모든 리스트가 정확히 3항목. 내용이 순서를 담을 때만 번호를 단다.
10. **요약 재진술** — "위 내용을 바탕으로", "이를 통해", "총정리하면".
    사용자는 앱 문구에서 에세이 서식을 기대하지 않는다.

## 다시 쓰기 규칙

- **사실 → 행동 → 기대 결과** 순서. "물을 마셨나요? 성대 점막은 하루 종일
  수분을 쓴다. 지금 한 모금이 오늘 남은 연습을 바꾼다." 같은 밀도.
- 버튼은 동사로 끝나고 결과를 그대로 말한다: "시작"이 아니라 "측정 시작".
  액션 이름은 흐름 전체에서 하나로 유지(버튼 "기록" → 토스트 "기록됨").
- 숫자는 단위와 함께: "몇 분"이 아니라 "5~10분", "조금"이 아니라 "20초".
- 전문 용어는 처음 나올 때 한 번만 풀이하고 그 뒤로는 그대로 쓴다.
  (SOVT → "입을 반쯤 막는 발성(빨대·허밍)" 1회, 이후 'SOVT')
- 존댓말은 해요체와 합니다체를 기능별로 구분: 안내는 합니다체,
  코칭 큐는 해요체. 한 문장 안에서 혼용하지 않는다.

## 적용 순서

1. 문자열 소스(Swift 뷰의 Text/String, JSON 콘텐츠, 알림 문구)를 전수 수집.
2. 체크리스트로 분류: [삭제] [수정] [유지].
3. 수정 문안은 그 자리의 정보 밀도를 낮추지 않는지 확인하고 반영.
4. 변경 후 화면 문맥(제목/본문/버튼 길이 제약)에서 다시 읽는다.
